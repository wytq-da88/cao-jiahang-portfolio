## 第一轮：从作品建立视觉身份

参考方法：[frontend-design](https://github.com/anthropics/skills/blob/main/skills/frontend-design/SKILL.md)、[distill](https://github.com/pbakaus/impeccable/blob/main/skill/reference/distill.md)。

> 以壁时的真实形态、CMF 和节气逻辑建立整站身份。先检查现有原图、展板和案例文字，列出可证实的设计决策及缺失证据。让首页同时表达作者、代表作和设计观点。
>
> 首屏将壁时作为视觉主体，标题与产品避免互相遮挡；把泛化口号改成能对应作品的一句话。用深色展示产品，用较明亮的正文承载研究和过程；金色只突出少数关键细节。字体、网格和图注服务作品阅读。
>
> 案例按照问题、设计依据、方案取舍、形态与材料、交互、结构及结果展开。重排展板内容时保留原始事实与高清查看入口。减少重复介绍和无功能的装饰。
>
> 输出变化前后对照、每处修改的依据，以及仍待作者提供的事实。不得把缺失的研究或制作过程补成已完成成果。

## 第二轮：用连续镜头解释产品

参考方法：[apple-design](https://github.com/emilkowalski/skills/blob/main/skills/apple-design/SKILL.md)。

> 在已确认的视觉方向内编排壁时的展示顺序：整体轮廓、材质纹样、节气模块、中央显示、底座结构、使用场景。每个镜头回答一个设计问题。
>
> 让滚动进度与画面变化有对应关系，反向滚动也应连续。导航和图片切换立即反馈，切换中允许再次操作。以小幅运动和自然收束表现器物的安静；悬浮、光效与缩放须服务具体说明。
>
> 优先使用用户原有图片与视频。有真实网页模型后再考虑旋转或结构交互；没有模型时采用明确的图像展示，不伪装为三维实物。正文和主按钮应在动效失败时仍可阅读与使用。
>
> 手机上以直接阅读和触摸操作为主，减少动态偏好下保留内容与状态提示。输出动效目的、触发方式、可打断方式和替代状态，再完成真实浏览器检查。

## 第三轮：从实际访问路径做精修

参考方法：[polish](https://github.com/pbakaus/impeccable/blob/main/skill/reference/polish.md)、[review-animations](https://github.com/emilkowalski/skills/blob/main/skills/review-animations/SKILL.md)。

> 保持已批准的风格、作品内容与信息结构，沿“首屏 → 精选作品 → 壁时案例 → 其他作品 → 简历与联系”实际使用网站。
>
> 先修阻断阅读与导航的问题，再检查图片裁切、文字换行、对比度、焦点、触摸目标、加载状态和动效一致性。核对所有资源及链接，尤其避免重现造型推导图片路径错误。
>
> 以真实设备尺寸检查桌面、手机和平板，并验证键盘与减少动态偏好。图片应提供合适尺寸，明确宽高，避免位移；视频按需加载，失败有可见的静态替代。
>
> 检查独立 GitHub Pages 路径、刷新、简历下载、联系方式、SEO 和分享图。每个结论附证据；未测试的设备或账号状态明确列出。完成第三轮时交付预览、验证记录、原始来源清单和可维护源码。
